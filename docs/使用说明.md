## 一、界面长什么样（先认路）

用浏览器打开 **http://localhost:5173** 后，页面从上到下分为三块：

```
┌─────────────────────────────────────────────────────────────────┐
│ 【顶栏 AppHeader】 左侧 Logo「HotPulse」  右侧：状态条 | 立即扫描 | 铃铛  │
├─────────────────────────────────────────────────────────────────┤
│ 【导航 AppNav】  [热点雷达][监控词][平台发现][搜索][设置]  ← 五个 Tab 按钮   │
├─────────────────────────────────────────────────────────────────┤
│ （可选）黄色「完成以下配置即可开始监控」引导条                              │
├─────────────────────────────────────────────────────────────────┤
│ 【主内容区】 当前 Tab 对应的页面（列表、表单等）                            │
└─────────────────────────────────────────────────────────────────┘
```

| 区域 | 在屏幕上的位置 | 你能做什么 |
|------|----------------|------------|
| 顶栏 | 最上方横条，滚动页面时也会吸顶 | 看扫描状态、点 **立即扫描**、看 **通知铃铛** |
| 五个 Tab | 顶栏正下方一排圆角按钮 | 切换 **热点雷达 / 监控词 / 平台发现 / 搜索 / 设置** |
| 主内容 | Tab 下方大块区域 | 具体操作见下文各章 |

**默认首页：** 打开网址后落在 **「热点雷达」** Tab（第一个 Tab 会高亮为白底）。

## 二、第一次安装（全部在终端里做）

下面所有 **「在终端执行」** 的步骤，默认指：

- **macOS：** 打开「终端 Terminal」应用  
- **Windows：** 打开「PowerShell」或「Windows Terminal」  
- **VS Code / Cursor：** 菜单 **终端 → 新建终端**（效果相同）

### 2.1 确认 Node.js 已安装

**在哪里执行：** 任意目录的终端均可（用来检查环境）。

```bash
node -v
```

- 若显示 `v18.x` 或 `v20.x` 等 → 继续  
- 若提示 `command not found` → 先去 https://nodejs.org 安装 LTS 版本，安装后**关闭终端再重新打开**，再执行一次

### 2.2 进入项目文件夹

**在哪里执行：** 终端。

**你要去的目录：** 克隆下来的项目根目录，文件夹名一般为 `yupi-hot-monitor`。

```bash
# 示例：项目在桌面 lin 文件夹下（按你的实际路径改）
cd ~/Desktop/lin/yupi-hot-monitor
```

**怎么确认路径对了：** 终端里执行：

```bash
ls
```

应能看到 `client`、`server`、`docs`、`package.json` 等，**不要**只有 `src` 或只有 `node_modules`。

> 之后文档里写 **「在项目根目录执行」**，就是指：终端当前路径已经是这个 `yupi-hot-monitor` 文件夹。

### 2.3 安装依赖

**在哪里执行：** 项目根目录（上一步 `cd` 到的位置）。

```bash
npm run install:all
```

- 会分别安装 `server` 和 `client` 的依赖，需要几分钟  
- 完成后终端回到可输入状态，无红色 `ERR!` 即可

### 2.4 复制并编辑环境变量文件

**步骤 A — 在终端复制模板（项目根目录）：**

```bash
cp server/.env.example server/.env
```

**步骤 B — 用编辑器打开文件（二选一）：**

| 方式 | 操作 |
|------|------|
| VS Code / Cursor | 左侧文件树点开 `server` → 点开 `.env` |
| 记事本 | 用资源管理器打开 `yupi-hot-monitor/server/.env` |

**步骤 C — 在文件里找到这一行并改成你的密钥：**

```bash
OPENROUTER_API_KEY=sk-or-v1-你的真实密钥
```

- 密钥获取：https://openrouter.ai/settings/keys  
- **保存文件**（macOS `Cmd+S`，Windows `Ctrl+S`）

其余变量（Twitter、SMTP、GitHub）可先不改，后面需要再在 **设置** 页或 `.env` 里补。

### 2.5 创建数据库表

**在哪里执行：** 项目根目录。

```bash
npm run db:push
```

成功时会看到 Prisma 提示数据库已同步。

### 2.6（推荐）导入演示数据

**在哪里执行：** 项目根目录。

```bash
npm run demo
```

终端应出现类似 `Demo seed complete: 3 keywords, 4 hotspots`。  
这样第一次打开网页就能看到示例热点，不必先自己加词。

### 2.7 启动前后端

**在哪里执行：** 项目根目录。

```bash
npm run dev
```

**终端里应同时出现两行前缀：**

- `[server]` — 后端，端口 **3001**  
- `[client]` — 前端，端口 **5173**  

**不要关闭这个终端窗口**，关闭就等于关机。

**在浏览器操作：**

1. 打开 Chrome / Edge / Safari  
2. 地址栏输入：`http://localhost:5173`  
3. 回车  

**如何确认后端也正常：** 新开一个终端标签，执行：

```bash
curl http://localhost:3001/api/health
```

应返回包含 `"status":"ok"` 的 JSON。若连接失败，说明只开了前端、没开后端，请回到 **2.7** 用根目录 `npm run dev`。

## 三、每天怎么启动项目

以后每次使用，按下面做即可（不必重复 `npm install`，除非换了电脑或删了 `node_modules`）。

| 步骤 | 在哪里 | 做什么 |
|------|--------|--------|
| 1 | 终端 | `cd` 到项目根目录 `yupi-hot-monitor` |
| 2 | 终端 | `npm run dev` |
| 3 | 浏览器 | 打开 http://localhost:5173 |

**停止服务：** 在跑着 `npm run dev` 的那个终端里按 `Ctrl + C`（macOS 上也是 `Ctrl + C`）。

## 四、监控词 Tab：逐步操作

**怎么进入：** 浏览器页面中，顶栏 Logo 下方，点击第二个 Tab 按钮 **「监控词」**（带靶心图标）。  
点击后该按钮变白底，主内容区切换为监控词页面。

### 4.1 用模板一键导入（最快）

**在页面上的位置：** 进入「监控词」后，**最上方** 一块标题为 **「关键词模板」** 的卡片区域（带 ✨ 图标）。

对每一张模板小卡片：

| 步骤 | 操作 |
|------|------|
| 1 | 阅读卡片标题，如「AI 大模型」「AI 编程工具」 |
| 2 | 点击该卡片底部的蓝色按钮 **「一键导入」** |
| 3 | 等待右下角 Toast 提示「已导入 N 个…」 |
| 4 | 下方会出现对应关键词列表 |

若某个词已存在，会自动跳过，不会报错。

### 4.2 手动添加一个关键词

**在页面上的位置：** 模板区域**下方**，一块带圆角边框的 **输入区域**。

| 步骤 | 页面位置 | 操作 |
|------|----------|------|
| 1 | 左侧长输入框 | 输入文字，例如 `GPT-5` |
| 2 | 输入框右侧下拉框 | （可选）点击展开，选「AI大模型」「AI编程」等；默认「无分类」 |
| 3 | 最右侧蓝绿渐变按钮 | 点击 **「添加」**（带 + 号） |
| 4 | — | 列表顶部出现新词；右下角 Toast「关键词添加成功」 |

### 4.3 导出 / 导入 JSON 备份

**在页面上的位置：** 输入区域**正上方**、模板区域下方，右侧对齐两个小按钮。

| 按钮文字 | 作用 | 操作 |
|----------|------|------|
| **导出 JSON**（下载图标） | 下载当前所有关键词 | 点击 → 浏览器会下载一个 `.json` 文件 |
| **导入 JSON**（上传图标） | 从文件批量导入 | 点击 → 弹出文件选择 → 选之前的 json |

### 4.4 打开 / 关闭监控（是否参与定时扫描）

**在页面上的位置：** 每个关键词一行卡片，**左侧** 有一个横向 **开关（胶囊形）**。

| 开关状态 | 含义 |
|----------|------|
| 蓝色、圆点在右 | **已激活**，会参与「立即扫描」和定时扫描 |
| 灰色、圆点在左 | **已暂停**，不会自动扫这个词 |

**操作：** 用鼠标 **直接点击开关** 即可切换，无需点保存。

### 4.5 编辑关键词

**在页面上的位置：** 每张关键词卡片 **右侧**（鼠标移上去才显示更明显）。

| 步骤 | 操作 |
|------|------|
| 1 | 鼠标移到某一行关键词卡片上 |
| 2 | 点击 **铅笔图标** 按钮 |
| 3 | 屏幕中央弹出 **「编辑关键词」** 对话框 |
| 4 | 修改文字或分类下拉框 |
| 5 | 点击对话框底部蓝色 **「保存」** |
| 6 | 对话框关闭，列表更新 |

### 4.6 删除关键词

| 步骤 | 操作 |
|------|------|
| 1 | 鼠标移到该行卡片 |
| 2 | 点击 **垃圾桶图标**（在铅笔旁边） |
| 3 | 该词从列表消失；Toast「关键词已删除」 |

> 删除关键词 **不会** 自动删除热点雷达里已入库的旧热点。

### 4.7 查看「上次扫描」时间

**在页面上的位置：** 关键词文字下方一行小灰字，例如 **「上次扫描 5 分钟前」**。  
只有该词至少被扫描过一次才会显示。

### 4.8 添加完词后，建议立刻扫一次

见 [九、顶栏：立即扫描](#九顶栏立即扫描与通知)。

## 五、热点雷达 Tab：逐步操作

**怎么进入：** 点击导航第一个 Tab **「热点雷达」**（闪电/活动图标）。  
这也是打开 http://localhost:5173 时的默认页。

### 5.1 看统计卡片

**在页面上的位置：** Tab 下方 **第一行**，通常 3～4 个并排小卡片。

显示例如：总热点数、今日新增、紧急数量等，**只读**，无需点击。

### 5.2 看「近 7 天趋势」图

**在页面上的位置：** 统计卡片 **下方** 一块标题为 **「近 7 天趋势」** 的区域。

- 左侧：按日的竖条图  
- 下方：按来源的横条  

没有数据时这一块 **不显示**，属正常。

### 5.3 找到「实时热点流」和导出报告

**在页面上的位置：** 趋势图下方。

| 元素 | 位置 | 说明 |
|------|------|------|
| 标题 **「实时热点流」** | 左侧，带火焰图标 | — |
| 按钮 **「导出报告」** | 标题同一行 **右侧** | 带下载图标 |
| 小字 **「自动扫描（间隔见设置）」** | 导出按钮旁边 | 提示语 |

**导出报告操作：**

| 步骤 | 操作 |
|------|------|
| 1 | 点击 **「导出报告」** |
| 2 | 按钮下方弹出小菜单：**今日 / 近 7 天 / 近 30 天** |
| 3 | 点击其中一项 |
| 4 | 浏览器自动下载 `.md` 文件；Toast「报告已下载」 |

### 5.4 筛选与排序

**在页面上的位置：** 「实时热点流」标题下方，**筛选工具条**。

**第一行工具条：**

| 控件 | 位置 | 操作 |
|------|------|------|
| 排序按钮组 | 左侧，带 ⇅ 图标 | 直接点 **最新发现 / 最新发布 / 重要程度 / 相关性 / 热度综合**，当前选中项为蓝底 |
| **「筛选」** 按钮 | 排序右侧 | 点击 **展开/收起** 下方更多筛选项 |
| **「重置」** | 有筛选时出现 | 一键清空所有筛选 |

**点击「筛选」后展开的第二行（下拉）：**

从左到右一般为：**来源、全部等级、全部关键词、全部时间、全部**（真实性）等，每个都是一个小下拉按钮，点击后选具体值。

### 5.5 展开 / 折叠所有 AI 理由

**在页面上的位置：** 热点列表 **上方右侧**（仅当列表里有带 AI 理由的卡片时才出现）。

点击 **「展开所有理由」** / **「折叠所有理由」** 切换。

### 5.6 浏览一条热点卡片

**在页面上的位置：** 筛选条 **下方**，一条条深色圆角卡片。

每张卡片上常见元素：

| 元素 | 位置 | 点击效果 |
|------|------|----------|
| 彩色标签 `urgent` `high` 等 | 卡片顶部左侧 | 只读 |
| 来源名、监控词小标签 | 标签右侧 | 只读 |
| **标题**（白色大字） | 中部 | **点击 → 右侧滑出详情抽屉** |
| 「展开理由」「原始内容」 | 摘要下方小字链接 | 点击展开折叠 |
| **删除（垃圾桶）** | 卡片右上（**鼠标移入卡片** 才显示） | 点击 → 浏览器确认框 → 确定后删除 |

### 5.7 翻页

**在页面上的位置：** 列表 **最底部中央**。

- **左箭头 `<`**：上一页  
- **数字 1 2 3…**：跳页  
- **右箭头 `>`**：下一页  
- 右侧文字 **「共 N 条」**

### 5.8 列表为空时

**在页面上的位置：** 主内容区中央虚线框。

| 提示文字 | 你应该 |
|----------|--------|
| 还没有监控关键词 | 点文中链接 **「去添加监控词 →」**，或终端执行 `npm run demo` |
| 尚未发现热点 | 点顶栏 **「立即扫描」**，或去 **设置** 调短扫描间隔 |

## 六、平台发现 Tab：逐步操作

**怎么进入：** 点击导航第三个 Tab **「平台发现」**（指南针图标）。

本 Tab 与「监控词 + 立即扫描」不同：**不需要先添加关键词**，直接从 GitHub、微博、Hacker News、Bilibili、Hugging Face 等平台拉取**当前榜单**，并对榜单前几条做 AI 分析。适合「今天各平台在火什么」的快速浏览。

### 6.1 选择平台、时间、排序

**在页面上的位置：** 主内容区最上方大卡片，标题 **「平台发现」**，副标题 **「纯榜单 · 无关键词 · Top 5 AI 分析」**。

| 区域 | 位置 | 操作 |
|------|------|------|
| **选择平台** | 第一组圆角按钮 | 点 **GitHub / 微博热搜 / Hacker News / Bilibili / Hugging Face** 之一 |
| 说明小字 | 平台按钮下方 | 提示 Google/Bing 未纳入发现模式 |
| **时间范围** | 第二组按钮 | **今天 / 近 7 天 / 近 30 天**（部分平台可能只支持其中几项） |
| **排序指标** | 第三组按钮 | 如 **综合热度、Star 数、播放量** 等，因平台而异 |
| GitHub 提示 | 选「最近更新」时 | 说明按仓库最后推送时间筛选，非单文件修改时间 |

切换平台、时间或排序后，页面会**自动重新拉榜**（无需再点刷新，也可手动点）。

### 6.2 刷新榜单与快照

**在页面上的位置：** 排序按钮下方，宽按钮 **「刷新榜单」**（青蓝渐变 + 刷新图标）。

| 步骤 | 操作 |
|------|------|
| 1 | 点击 **「刷新榜单」**（或等待切换选项后的自动加载） |
| 2 | 等待转圈结束；Toast 提示加载条数及 Top N 已 AI 分析 |
| 3 | 按钮下方小字：抓取时间；非缓存时会显示 **「快照已保存」** |

**快照是什么：** 每次**非缓存**的成功刷新，会把当次完整榜单存入数据库，供后面的 **AI 洞察** 和 **快照趋势图** 使用。缓存命中时不会重复存快照（小字会提示「缓存（改排序后请点刷新）」）。

### 6.3 AI 热点洞察面板

**在页面上的位置：** 刷新区域**下方**，紫青渐变边框卡片，标题 **「AI 热点洞察」**（✨ 图标）。

| 元素 | 操作 |
|------|------|
| **今日洞察 / 近 7 天 / 近 30 天** | 切换统计周期 |
| 折叠标题行 | 点击可收起/展开面板 |
| **重新生成** | 强制调用 AI 重新写总结（耗 API） |
| 关键词条形图 | 点击某个词 → **筛选下方榜单**，只显示标题/正文含该词的结果 |
| **清除关键词** | 榜单上方，取消筛选 |
| 主题标签、一段总结 | AI 或规则生成的可读摘要 |
| 底部统计 | 如「基于 N 次快照、M 条榜单条目」 |

**注意：** 洞察依赖历史快照。若显示「快照不足」，请对同一平台多点击几次 **「刷新榜单」**（至少 2 次非缓存保存）后再看 **近 7 天** 洞察。

### 6.4 「近 7 天快照趋势」图

**在页面上的位置：** 洞察面板**下方**（至少已有 **2 次** 快照趋势数据时才显示）。

| 含义 | 说明 |
|------|------|
| **每一根竖条** | 代表 **一次「刷新榜单」** 保存的快照，不是「一天一根」 |
| **柱高** | 当次榜单抓到的 **条目数量**（通常接近 30，所以看起来差不多高） |
| **下方日期** | 快照日期（月-日），同一天刷多次会显示 **相同日期**（如多个 `06-02`） |
| **悬停柱子** | 若有数据，可看到当次 **榜首标题** |

这与 **热点雷达** 里的「近 7 天趋势」不同：雷达图统计的是**已入库热点按天数量**；发现页统计的是**平台榜单刷新次数**。

## 十一、常见问题

### Q1：终端里 `[vite] proxy error` / `ECONNREFUSED`

**原因：** 只开了前端，后端 3001 没起来。

**处理：**

1. 关掉当前终端里错误的进程（`Ctrl + C`）  
2. **在项目根目录** 重新执行：`npm run dev`  
3. 确认终端里 **同时** 有 `[server]` 和 `[client]` 日志  

### Q2：黄色引导条一直不消失

按条检查：

1. `server/.env` 里是否填了有效的 `OPENROUTER_API_KEY`  
2. **监控词** 里是否至少有 1 个词（或执行过 `npm run demo`）  
3. 引导条右上角 **×** 可暂时关闭（会记在浏览器本地，刷新可能再出现）

### Q3：立即扫描很久没新热点

1. **设置** → 点 **「保存设置」** 前确认数据源有启用  
2. **设置** 最下方 **立即检测** 看哪些源 `failed`  
3. **监控词** 确认开关为蓝色（激活）  
4. Google 等源失败可先在 **设置** 里关掉，保留 Bing、Hacker News 等  

### Q4：平台发现趋势图很多柱子、日期都一样

**原因：** 图表按 **每次刷新** 画一根柱，不是按自然日汇总；同一天多次刷新会都标成同一天（如 `06-02`）。

**处理：** 属正常现象；若只想看日维度趋势，请用 **热点雷达** 的「近 7 天趋势」。

### Q5：AI 热点洞察提示快照不足

对当前平台多点击几次 **「刷新榜单」**（确保出现「快照已保存」且非纯缓存），再切换 **近 7 天** 洞察或点 **重新生成**。

### Q6：邮件 / Webhook 没收到

1. 邮件：必须先改 `server/.env` 里的 `SMTP_*` 和 `NOTIFY_EMAIL`  
2. **设置** 里打开对应开关后点 **「保存设置」**  
3. Webhook：先点 **「发送测试」** 成功，再依赖正式热点（仅 high/urgent）

### 13.2 按「你在页面上看到的功能」对照技术

#### （1）安装与启动（终端里做的那些事）

| 你做的操作 | 背后技术 | 说明 |
|------------|----------|------|
| `npm run install:all` | npm、Node.js | 分别安装 `server/`、`client/` 依赖 |

| 界面元素 | 前端技术 | 后端 / 其它 |

1. **node-cron 无关**，这是一次 HTTP 触发的任务

3. `ai.ts`：**OpenRouter** 做 `expandKeyword`、`analyzeContent`  
4. `hotspotFilters.ts`：新鲜度、去重、相关性规则过滤  
5. **Prisma** `hotspot.create` 入库，写 **Notification**  
6. **Socket.io** `emit('hotspot:new')`、**nodemailer** / **webhook**（若开启）

### 13.3 十个数据源分别用什么技术抓

你在 **设置 → 数据源** 里开关的每一项，对应后端文件与抓取方式如下：

| 数据源 | 后端模块 | 抓取方式 | 外部依赖 |
|--------|----------|----------|----------|
| **Twitter / X** | `services/twitter.ts` | 第三方 **Twitter API**（twitterapi.io 风格） | 环境变量 `TWITTER_API_KEY` |
| **Bing** | `services/search.ts` | **axios** 请求 Bing 搜索页 + **cheerio** 解析 HTML | 无 Key，可能限流 |
| **Google** | `services/search.ts` | 同上，抓 `google.com/search` HTML | 无 Key，易被反爬 |
| **DuckDuckGo** | `services/search.ts` | 抓 `html.duckduckgo.com` HTML | 无 Key |
| **Hacker News** | `services/search.ts` | **Algolia HN API**（`hn.algolia.com`）官方 JSON | 无 Key |
| **GitHub** | `services/communitySearch.ts` | **GitHub REST** `search/repositories` | 可选 `GITHUB_TOKEN` 提限额 |
| **Hugging Face** | `services/communitySearch.ts` | **Hub API** `huggingface.co/api/models` | 无 Key |
| **搜狗** | `services/chinaSearch.ts` | HTML 抓取 + cheerio | 无 Key |
| **Bilibili** | `services/chinaSearch.ts` | B 站搜索/热门接口封装 | 无 Key |
| **微博热搜** | `services/chinaSearch.ts` | 微博热搜相关抓取 | 无 Key |
| **账号检测** | `chinaSearch.detectAndFetchAccount` | 根据关键词猜平台账号 | 随搜索附带 |

统一聚合入口：`services/aggregateSearch.ts`（并行、去重、统计每源成功/失败）。

### 13.4 AI 能力用在哪里（OpenRouter + DeepSeek）

| AI 能力 | 何时触发 | 技术 | 默认模型 |
|---------|----------|------|----------|
| **查询扩展** | 每个监控词开始扫描时 | `expandKeyword()` | `deepseek/deepseek-v3.2` |
| **内容分析** | 每条待入库内容、搜索每条结果 | `analyzeContent()` | 同上 |
| **发现 Top5** | 平台发现刷新榜单 | `analyzeDiscoveryTopItems` | 每榜前 5 条 |
| **热点洞察** | 洞察面板生成 | `insightAi.ts` | 跨快照主题/总结 |
| **预匹配** | 分析前本地正则 | `preMatchKeyword()` | 不耗 API，减调用 |
| **无 Key 降级** | 未配置 `OPENROUTER_API_KEY` | 规则 fallback | 默认分较低 |

分析输出字段（写入 **Hotspot** 表）：`isReal`、`relevance`、`relevanceReason`、`keywordMentioned`、`importance`、`summary`。

SDK：`@openrouter/sdk`；统计：`services/aiStats.ts`（设置页可查看调用次数）。

### 13.5 通知与推送用了什么

| 渠道 | 技术 | 触发条件 | 配置位置 |
|------|------|----------|----------|
| **站内通知** | Prisma **Notification** 表 + 铃铛 UI | 入库、手动保存 | — |
| **WebSocket 实时** | **Socket.io** 服务端/客户端 | 新热点、新通知 | 自动连接当前站点 |
| **浏览器 Toast** | 前端 `Toast.tsx` | 收到 socket 或 API 成功 | — |
| **邮件（即时）** | **nodemailer** + SMTP | `high` / `urgent` 热点 | `server/.env` SMTP_* |
| **邮件（日报）** | **node-cron** `0 8 * * *` + `sendDigestEmail` | 设置开启每日日报 | 同上 |
| **Webhook** | **axios** POST JSON | `high` / `urgent`；钉钉/飞书格式不同 | 设置页 URL + 类型 |

### 13.9 Agent Skills（与 Web 并列的另一套技术）

| 组件 | 技术 |
|------|------|
